## Rules for using this draft

- Every row is **Pending**. A source page is not the same as an approved image.
- Do not download, add to the app, or connect images to events until the selected asset is approved under the team's process.
- Choose the actual image on the source page and record its **direct image URL**, full credit line, and any rights/reuse restrictions. Do not assume all images hosted on NASA pages are NASA-owned; some are credited to third parties.
- Proposed filenames below are suggestions only. Change them to match the approved filename and team convention.
- Keep the physical `data/media/sample-*.svg` files. Per the task, actual media files in `data/media/` stay local and out of Git.
- After approval, add a media record to `data/content.json` with a unique `id`, exact `file`, useful `alt`, `caption`, and `credit`; then reference that media ID from the event's `mediaIds` array.
- Use the official Media Log location/process if the project leader provides one. This draft does not replace museum or project-leader approval.

## Proposed approval workflow

1. Confirm with the project lead who approves images and where the official Media Log should live.
2. Select one candidate image for an event and capture its direct asset URL and exact credit/reuse information.
3. Submit that row for approval; keep the status Pending until approved.
4. After approval, use the final approved filename in `data/media/`, update the media record and the event's `mediaIds`, then test locally offline.
5. When all approved media are collected, create the requested backup ZIP and put it in Drive's `3-Kiosk-Backups` folder.
